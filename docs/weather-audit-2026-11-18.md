# 天气项目排查与修复记录

2026 年 11 月 18 日检查了 Python 提取器、气象适配器、本地 HTTP 服务、Three.js 地球、经典风场页面、Leaflet、MapLibre、Cesium 和 iframe 客户端。Google 3D Maps 原型、交易工作台和设计稿也纳入了入口及引用检查。修改基于已有工作树，未提交。

## 已修复的问题

| 位置 | 触发条件与影响 | 修复结果 |
| --- | --- | --- |
| ERA5 风场 | 东向分量为正、北向分量为零时，输出把西风报成南风。静风也会得到一个角度。 | 按气象来向计算，四个主方向分别验证。静风保留零风速，省略方向。Three.js 点位也显示静风，并将取整后的 360° 归回 0°。 |
| ERA5 命令行 | 从已有网格文件读取时，用户传入的 `--levels` 会被忽略。 | 风场与标量场都按所选气压层输出。 |
| 网格生成 | 三处相同的循环遇到零步长或负步长会持续增加列表。 | 共用有限、正数步长检查，并发现浮点数已经无法推进时退出报错。 |
| 网格插值 | 融合和降水对每个目标点反复线性搜索两根坐标轴。单行、单列以及恰落在有效节点的点，还可能被不参与计算的缺测邻点污染。 | 升序、降序轴都使用二分查找，仅对有贡献的节点求值，保留原有边缘钳制规则。 |
| 多源融合 | 单层数组放在 `data` 时可能被当作字典读取。负值、非有限权重可能产生不可用结果。 | 区分多层映射与单层数组，检查权重，并在方差与均值中一致排除非有限值。融合和降水 CLI 同时接受来源数组和带 `sources` 的对象。 |
| 降水集合 | 某个来源缺测时，剩余来源没有重新归一化，可能把实际 12 mm/day 算低。全零模式与有雨参照做比值订正还会除零。 | 每个格点按可用权重计算。无法估计乘法订正时保留原值。去除第二遍等价插值和无消费者的整网格方差计算；加权模式使用加权离散度及对应名称。 |
| 气溶胶与辐射 | AOD、净辐射或强迫值为零时，数值字段正确，文字却显示缺测。 | 文字只对缺值显示 N/A，读取不完整的 AOD 行时采用已有的缺测处理。 |
| EXIF 和地图标定 | 字节形式的西经、南纬可能读成正值，二进制海拔参考字节可能引发异常。共线控制点可以拟合出任意二维解。 | 识别字节标签，校验坐标数值和半球，校验标定矩阵的秩，两个坐标分量一次拟合。边界框拒绝非有限坐标。 |
| NMC 下载和本地接口 | `2026061016` 可能按含分钟的格式误读。图片下载中断或两个请求同时更新同一个 latest 文件时，可能留下半张图或读错请求的图。 | 按长度识别紧凑时次。分块下载、核对可用的长度头、成功后原子替换，并保证每个请求的下载和识别不会互相穿插。 |
| 云高点查与预热 | 每次点击都重新解析约 18.6 MB 的全球对流 JSON。当前渲染器预热时也会先生成旧版圆形云核。 | 最近一个来源版本共用原始数值数组，按文件与元数据版本失效。形状和点查路径跳过旧云核计算，兼容接口仍可按需生成。高度预热合为一次批量准备。 |
| Three.js 云层 | 加载过近景云以后，相机移动时会扫描整个地球的采样分区。远处也会运行筛选，一帧内还会重复准备相机。 | 按分区方向的 z 分量建索引，保守扩大候选范围以覆盖极区和经度接缝，保留最终相交判定。远景跳过筛选，同一帧复用已准备的视图。 |
| 云高边界与大气 | 云底裁到显示基准面后，低于基准面的云顶可能产生倒置包围范围，前端会拒绝整份字段。大气着色器仍使用高远近比下不稳定的远平面反投影。 | 排除倒置区间，遇到旧无效缓存时重新生成。大气与云使用相同的稳定射线构造。 |
| 图层加载与缓存 | 同一 URL 的并发响应重复计入内存预算，JSON 和二进制共用键。快速切层会继续处理上一个气压层。同批次风温网格加载失败后，重试按钮可能无效。 | 缓存按表示类型区分，相同超时且可共享的请求合并。切换中止旧请求，重试按缺失的数据阶段重新加载。服务更新失败但仍有数据时，页头标注“缓存预报”。 |
| HTTP 传输 | 大体积 GeoJSON 未压缩，压缩结果只按文件数限制。服务还可能把资产授权带到其他来源；按瓦片、批次保存的锁随运行时间累积。 | GeoJSON 支持 gzip、ETag 和条件请求，压缩缓存同时设字节上限。限制解压输出，授权按来源传递，闲置锁可回收。 |
| 回放与嵌入 | 较慢的旧帧可能覆盖后选帧，慢网自动播放会不断追赶。Cesium 未使用清单指定的默认序号。iframe 的 payload 可覆盖路由字段，重复请求编号会串扰。 | 两版回放只应用仍有效的响应，自动播放等待当前帧完成。Cesium 使用有效默认序号。客户端固定协议字段、检查返回来源、拒绝冲突编号并清理发送失败的请求。 |
| 已确认废弃的实现 | 发现两个无调用的 Cesium 相机函数、旧着色器参数、重复构建写入和无效中间量。静态数据目录的例外规则也把 Finder 元数据重新纳入 Git。 | 清理无调用实现与无效计算，修正文档中的旧底图和云图入口说明，恢复 Finder 文件忽略规则。 |

ERA5 的方向约定采用欧洲中期天气预报中心的定义。其文档同时说明不同语言的 atan2 参数顺序有差异。[ECMWF 风速与气象风向说明](https://confluence.ecmwf.int/pages/viewpage.action?pageId=133263625)

## 性能对照

同一台机器以同一输入分别运行修改前后的实现。下列耗时覆盖指定操作。

| 测量 | 修改前 | 修改后 | 核对 |
| --- | ---: | ---: | --- |
| 同一快照连续点查三个相邻位置 | 116.64、97.32、105.70 ms | 197.96、0.08、0.02 ms | 坐标、预报批次和返回数值一致。首次访问增加数组转换开销，缓存只保留一个批次。 |
| 1,440 × 721 网格，20,000 次双线性采样 | 729.2 ms | 28.0 ms | 同一坐标序列与返回和，另有升降序、缺测和单轴回归。 |
| 安哥拉真实云场 42,254 个分区，200 次相机更新及分区选择 | 115.3 ms | 6.6 ms | 两次候选分区累计数均为 906。数据来自本机 Node 环境，整页帧率还受 GPU 和底图影响。 |

| 云砧形态与全球接缝 | GFS 原网格为 0.25°。缺测处的上部云是邻近推断。观测连通域在二维数组上划分，首尾经度列的云区有可能分开。 | 需要跨接缝及高纬观测样例，并用独立云高资料评估延伸范围与误差。 |
| 旧入口、原型与兼容 API | 经典页、MapLibre、Cesium、Google spike 和旧云接口仍存在，可从文档或独立 URL 调用。`trading-workbench/` 是带模拟行情的独立页面，`docs/demo/` 是未提交的设计稿。 | 先确认外部嵌入方、发布范围和归档需求，再决定哪些入口退役。 |
| 第三方服务和终端覆盖 | 实测中 Google/Cesium 相关资源和公开 CDN 的耗时不稳定，GFS 更新遇到过一次 TLS 握手超时，稍后成功发布新批次。 | 商用账号额度、不同网络、Safari/iOS、低端 GPU 的长时间表现仍待实机验证。 |

| NMC 原图回看 | 接口按配置覆盖 latest 文件，返回地址含修改时间。后续请求仍会替换这个路径的内容。 | 如果业务要求历史 GeoJSON 始终能找回对应原图，需要另定历史图片的存储和保留期。 |

## 验证范围

- 从本地服务加载真实天气快照 `20261118T06Z-f006-0p5-v2`（北京时间 11 月 18 日 20 时有效），执行近景云加载和快速切层。GPU 读回检查了云形缺口、四档缩放、地平线和海面覆盖。
- 在真实浏览器中运行 MapLibre 与 Cesium 回放控件，用可控的时次文件延迟模拟乱序。在固定版本引擎资源和测试数据下，两版都显示最后选择的要素。生产 CDN 与商业瓦片的持续可用性另行验证。
- Python 自动化测试 173 项、前端 126 项全部通过。另执行五条 CLI 示例、Python 静态检查及本地模块与静态页面直接引用检查。在隔离目录重建前端，vendor、Draco 解码器与第三方声明和仓库文件逐字节相同。
- 检查独立演示页可访问。整套商业地图、第三方账户、全部浏览器和连续多日运行的行为仍有验证边界。
