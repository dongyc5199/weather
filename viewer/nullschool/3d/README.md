# Three.js 三维气象预览

入口：<http://127.0.0.1:8080/3d/>。和经典页面共用 `weather-earth serve --port 8080`、GFS 快照以及每 30 分钟的数据更新。

默认底图为 Google 实景三维。大阪入口：<http://127.0.0.1:8080/3d/?view=osaka&basemap=google&level=850hPa>。菜单“大阪实景”定位到中之岛附近；“卫星地形”或 `basemap=terrain` 可切回 Cesium 地形、Esri 影像和 OSM 建筑。

## 已接入

- Three.js 0.187.0 + 3d-tiles-renderer 0.5.4；统一三维相机、深度和地形/影像渲染。
- Google Maps Photorealistic 3D Tiles（Cesium ion 资产 2275207）：完整的带纹理地表和城市模型，保留源模型的屋顶、立面纹理与材质。
- Cesium World Terrain：读取已有 `viewer/earth.config.local.js` 的配置，服务端换取临时地形令牌；不把长期令牌写入新页面或代码仓库。
- Esri World Imagery 卫星底图。
- Cesium OSM Buildings（资产 96188）：独立的三维建筑图层，沿用现有 Cesium 授权；保留 OpenStreetMap 归因和供方账户提示。
- Natural Earth 国界、海岸线、主要河流与湖泊，以及 DataV 中国省、市级/省直辖行政单元边界。地理参考线独立显示在气象填色和风线上方。原始来源和转换说明在 `../data/geography/sources.json`。
- Sfc 与七个等压层的 GFS 风温数据，独立三维填色、点位插值与风线动画。风温层使用同批次 HGT 位势高度；填色低于真实地表时贴地，风线与等值线保留地下气压层屏蔽。
- 位势高度等值线与海平面等压线：独立开关、原始值标注、同批次 GFS HGT/PRMSL 数据。
- NASA GIBS Himawari AHI 红外云图，按源站最新观测时间取图，每 5 分钟检查。
- 全球、中国、珠峰近景、风层侧视、西安城区及建筑近景预设；左键移动、滚轮缩放、右键倾斜。

## 构建和数据准备

```bash
cd viewer/nullschool/3d
npm ci
npm run build
```

`vendor.js` 是固定版本依赖的浏览器 bundle，随源码保留，运行预览不需要依赖外部 JavaScript CDN。

在仓库根目录更新行政区数据：

```bash
.venv/bin/python -m weather_geo_extractor.earth_layers prepare-admin
```

`data/earth3d-cache/` 为可再生的气象 PNG 瓦片缓存，已被 Git 忽略。下载的行政区 GeoJSON 与来源记录位于 `data/geography/`。

## 表达范围

实景三维使用既有 `viewer/earth.config.local.js` 中的 `cesiumIonToken` 换取 Google 可视化入口。服务端 `/api/earth/3d/photorealistic` 不返回长期账户令牌，HTTP 响应为 `no-store`；客户端使用官方 Google 会话插件处理后续请求，凭据仅发送到 HTTPS 的 `tile.googleapis.com`。Google 模型不进入 Esri 的压缩响应/预览缓存，也不进入本地地形文件缓存，网络请求遵循源站 HTTP 缓存策略。渲染器活动资源缓存上限约 512 MiB，最近离开视野的瓦片使用已有的软保留策略。

该模式使用 Google 自带的完整三维底图，不叠加 OSM 白模、Esri 底图或 Cesium 地形。风场、气温和行政边界仍可叠加；天气图层不改写原有摄影纹理或驱动模型额外细分。Google Maps 标志、当前可见瓦片的数据归因以及 Cesium 账户提示保留在页面下方。API 与 Google Earth 产品的覆盖、影像日期、标签和渲染表现不保证完全一致，未覆盖区域不会补造建筑纹理。

OSM 建筑入口：`/3d/?view=buildings&basemap=terrain&buildings=1`。建筑形状与高度来自 Cesium OSM Buildings，数据覆盖和完整度随地区变化；未覆盖的位置仍显示卫星影像。建筑和底图是独立的数据层，页面不补造缺失建筑。点选建筑时显示的是模型表面的近似高程，而非离地建筑高度。

建筑在相机高度低于 80 km 时开始加载，超过 100 km 时暂停；独立缓存上限为 128 MiB，最多四路下载和两路模型解析，关闭图层会释放资源。关闭真实地形时暂停建筑；在地形关闭状态下开启建筑会同时开启真实地形。长期账户令牌留在服务端，浏览器只取得建筑资产的临时令牌，授权请求仅发给资产对应源站。

Draco 与 Meshopt 解码支持随前端依赖一起提供，Draco 解码文件在 `decoders/draco/`，许可证在 `licenses/` 和 `THIRD-PARTY-NOTICES.txt`。`npm run build` 同时更新依赖包和本地 Draco 文件。

供方归因图标使用 `https://assets.ion.cesium.com/ion-credit.png` 的完整本地副本，避免图标网络超时；数据来源链接与账户提示仍按供方返回内容显示。

真实三维地形来自高程瓦片。风线和气象层按 GFS 各等压面的 HGT 位势高度换算近似几何高度；Sfc 风使用模式地形以上 10 m，气温使用模式地形以上 2 m。温度和风速填色采用气象层与实际显示地表中较高的表面，地形高出气象层时直接贴地着色，颜色仍对应所选气压层的原始数值。风线和位势高度等值线继续由同批次地表气压与高度屏蔽地下部分。风速动画经过时间缩放，目前仍为各层水平风，没有垂直速度或连续三维流场。

“风温层高度放大”默认 1×；1–20× 同时改变等压层风线和温度面离地的显示距离，不改变风速、风向、气温或原始位势高度；Sfc 始终使用 10 m 风和 2 m 气温。使用“风温层侧视”可以比较 850/500/250 hPa 等层的离地距离。温度面独立于地图瓦片，开关和切层不会重建底图；点击温度面时按温度面的交点查询经纬度和数据。

温度和风速填色以当前同批次网格生成浮点纹理。`WeatherCompositor` 每帧保存实际底图的颜色和深度，填色在原气象层交点与较高地表之间选择可见表面，因此既覆盖高山，也处理 Google 远景简化模型抬高造成的缺口。贴地只改变显示位置，颜色仍来自所选气压层；真缺测、网格/时次不匹配仍不补造数据。切换数据时立即清除旧面，等待新高度后恢复。`temperature=1` 可在链接中开启温度面。

底图深度独立保存并原样提供给后续风线、位势高度线、等压线标注等绘制；填色不回写深度，也不修改等值线输入、原始高度、地下掩码或高度放大规则。点击贴地区域会查询实际地表交点，并在点位信息中标明填色贴地。DPR 2 使用原生像素深度，避免再乘 MSAA 缓冲预算；DPR 1 保留抗锯齿。

城市近景还需区分贴地与前景遮挡：当前景建筑低于所选高空气象层，但沿视线更靠近相机时，只遮住远处填色，不把高空颜色涂到建筑上。只有实际表面高于该层时才接收贴地颜色；点击查询沿用同样的遮挡判断。2026-11-11 回归验证共 97 项前端测试与 19 项 GPU 检查通过，新增楼体遮挡/无遮挡天空的温度和风速案例，同时保留高地贴色和等高线深度案例。

## 风场总览

高视角的目标粒子数按可见地球包围框的 CSS 像素面积平方根乘以 8 计算，移动设备为 75%，总分配上限 10,000；生成点只接受实际可见的有效风层。低视角平滑降低数量和速度。使用 40 ms 固定步长保留余数，远景轨迹最长 1.8 秒、近景 0.65 秒，并按每段投影速度以约 96 CSS 像素作为尾迹长度预算；强风或放大时更早淡去。尾部逐渐变细、边缘柔化，避免白色长线堆积覆盖填色。每约 4 秒随机重生，按原始风速在 0–15 m/s 间细分明暗。线条自定义颜色、宽度、透明度和线型继续生效。动画时间经过视觉缩放，点选的风速数值仍是 GFS 原始 U/V 插值结果。

动画速度使用视线交点处的角度投影比例校准。地球放大到填满屏幕后，仍跟随实际投影放大率调整时间倍率，避免旧版按可见高度固定缩放导致区域视野中的风线过快、过长。近景继续平滑过渡到较低倍率，三维高度与原始 U/V 不变。

默认开启风速填色，菜单“填色”可切换“无 / 风速 / 气温”。`color=wind|temp|none` 可随链接保存选择；旧 `temperature=1` 继续开启气温。风速先分别插值 U/V，再计算矢量模长，使用项目内经典版的 0–100 m/s 色标，界面图例换算为 0–360 km/h；与风线共享同一批次的高度，填色在更高地形上贴地显示。色带使用独立三维数据面，不请求风速 PNG 瓦片。

相机高于 1,000 km 时，风线使用总览遮挡规则；降到 600 km 以下恢复真实地形/建筑深度遮挡，两阈值避免反复切换。温度和风速填色在各视角均按气象层与实际地表的较高表面显示，不再用远景开关绕过深度。因透视投影、实景底图和显示方式与经典版不同，画面不保证逐像素相同。

## 气象等值线

菜单“等值线”提供两个独立开关，链接参数分别为 `heightContours=1` 和 `isobars=1`：

- **位势高度线**（金色）：在所选等压层上按原始 HGT 取等值线，线条跟随该层高度和显示放大倍率，数值始终为原始位势高度。1000/850/700 hPa 默认间距 30 m，500 hPa 为 60 m，250 hPa 为 120 m，70 hPa 为 240 m，10 hPa 为 480 m。Sfc 不显示该图层。
- **海平面等压线**（浅蓝）：使用 NOAA GFS 的 `PRMSL:mean sea level`，Pa 换算为 hPa 后以 4 hPa 间隔取线。线条投影到地图表面供天气分析，不受高空高度放大影响。它不是地面 `PRES:surface`，也不由 HGT 临时推算。点选位置可查看同批次海平面气压。

新增接口 `/api/earth/3d/pressure/<snapshot>` 从当前风温快照对应的 NOAA 文件中按 Range 只读取 PRMSL 消息，并校验变量、海平面参考、单位、起报/有效时间和网格。缓存位于忽略的 `data/earth3d-cache/pressure/`。缺少匹配数据时显示不可用，不替换为地面气压或其他时次。

等值线在 Web Worker 中用 marching squares 生成，使用双线性鞍点判别、公共边拼接和日期变更线分段；地下或缺测格点不跨接。高空线用三维几何绘制，海平面线使用独立地图覆盖层。文字标注带原始单位，避免相互重叠并剔除地球背面的锚点；颜色与字体来自共享样式变量。切换等压层取消旧高空计算，同一快照的海平面线继续保留；预报批次更新时两层均清除旧结果。关闭图层会取消未完成请求和计算，重新开启可复用当前已完成数据。

数据定义参考：[NOAA GFS 产品清单](https://www.nco.ncep.noaa.gov/pmb/products/gfs/gfs.t00z.pgrb2.0p25.f000.shtml)。同时查看两层：`/3d/?view=china&basemap=terrain&level=500hPa&heightContours=1&isobars=1&temperature=1`。

## 线条样式

菜单“线条样式”可分别设置风线、位势高度线、海平面等压线、国家/省/市边界、河流与湖泊。支持颜色选择或十六进制输入、粗细、不透明度、实线/虚线/点线；两类等值线还可设置数值标注开关和字号。“恢复本层默认”只重置当前选择的图层。

默认值和图例使用共享 `styles/styles.css` 变量，个人设置保存到当前浏览器的 `weather-earth.line-styles.v1`。只保存与框架默认值不同的字段，刷新后恢复；不写入项目配置、不修改气象数据，也不随链接传到其他浏览器。存储受限时仍可调整当前显示，并在面板内说明无法保存。链接参数 `styles=wind|height|pressure|countries|provinces|cities|rivers` 可直接打开对应编辑项。

风线与高空等值线使用实例化宽线，使浏览器中的粗细设置实际生效，同时保留三维高度、深度和风线渐隐。地面等压线重绘已有 GeoJSON 纹理；行政边界和水系直接调整独立向量线。样式调整不重新下载数据或生成等值线。数值标注与线条颜色同步，图层关闭时可先保存外观，开启后使用。

2026-11-09 样式验证：前端 70 项测试通过。浏览器验证了三类气象线的实时样式、刷新恢复、仅重置所选图层，调整过程中气象数据请求新增为 0；GPU 像素检查覆盖粗细、虚线/点线、颜色、不透明度和风线渐隐。1440/768/390 px 检查无布局失败；图层配色和既有 11–12 px 的来源/辅助注释保留，设置主体采用 14–16 px。统一盒模型修正了小屏菜单右侧控件被裁切的问题。

## 地理参考线

国界/海岸线、省市边界、主要河流和湖泊使用独立的前景向量线，保持 CSS 像素线宽并加轻微深色描边，不再因气象透明填色而变淡，也不依赖底图瓦片完成下载。地球背面的线按椭球可见面剔除。它们是地理定位参考，不参与气象面的高度或地下掩码计算。

静止时使用较详细的轮廓；实际拖动、缩放时切换到较简化的轮廓，参考线始终保留，风线继续按交互规则隐藏。停稳后恢复细节。简化水系保留 Natural Earth 重要性等级 1–4 的河流，包括黄河与长江；城市边界仅在开启后构建几何。共享行政边不重复加深，日期变更线按短路径连接。

中国行政边界先从完整多边形提取共享拓扑，连接成以交汇点为端点的唯一边链，再生成静止与移动两套几何。开启国家边界时，省界层只绘制省际内部边，避免 DataV 外轮廓与 Natural Earth 国界/海岸线叠画；关闭国家边界则恢复省级外轮廓。市界同样按当前开启的上级边界去重，原始行政区数据继续用于点位名称查询。

“水系”默认开启，`rivers=0` 可关闭。数据包含 Natural Earth 1:5000 万国界/海岸/水系，以及 1:1.1 亿国界/海岸/湖泊的概化版本（文件名中的 `50m/110m` 表示地图比例尺，不是米级精度）。河流资料见 [Natural Earth](https://www.naturalearthdata.com/downloads/50m-physical-vectors/50m-rivers-lake-centerlines/)。数据已打包为 `../data/geography/reference-lines.json`，运行时无需访问外部河流服务。

在本目录执行 `npm run prepare:geography` 可重建静态参考线。脚本使用固定的 Natural Earth 仓库提交及已有海岸/湖泊 TopoJSON，来源、许可和计数记录在 `../data/geography/sources.json`。省市边界继续使用现有 DataV 数据与坐标转换。

地理参考线验证包含独立开关、河流颜色/粗细/线型及恢复默认、温度和风速填色覆盖、静止点击不简化、拖动/滚轮期间保留简化线与停稳后恢复细节；样式和开关操作新增地理/气象数据请求为 0。另有 6 项 GPU 检查验证覆盖顺序、背面剔除与 Retina 线宽；1440/768/390 px 布局检查无失败。

## 兼容适配

以下卫星影像细分与本地瓦片缓存策略用于“卫星地形”模式；Google 实景三维使用自身的三维瓦片树与原始摄影纹理。

`overlays.js` 为固定的 3d-tiles-renderer 0.5.4 补齐区域覆盖层缺失时的 uniform 槽，并保护瓦片/覆盖层取消后的回调。地形几何不等待叠加层下载，先显示本地低精度底图，再补齐卫星影像。只初始化开启的图层和视野内的影像，卫星影像使用 512 像素。温度面、行政边界和水系不再通过该贴地覆盖层加载。

卫星影像单独驱动叶节点细分，目标约为一个物理屏幕像素对应一个纹理像素；天气与行政区开关不重建该细分树。卫星源最多请求到 19 级，使用 mipmap 和最高 8× 各向异性过滤改善斜视清晰度，渲染像素比最高为 2。单帧最多处理两次额外细分，保留已加载祖先作为后备。

原地旋转时，额外细分会等待相机稳定 250 ms；已展开的层级使用滞后区间，避免在误差阈值附近反复切换。最近离开视野的已加载瓦片有 20 秒软保留期，硬缓存容量仍优先执行。卫星图另有 64 MiB 的压缩响应缓存，命中后直接复用，不再排队访问远端。

已加载影像保留在最多 32 MiB 的低分辨率预览缓存中。新瓦片先使用覆盖其地理范围的已有影像，按相同地图投影重新计算纹理坐标，高清纹理就绪后自然覆盖。下载优先级随当前可见区域更新；已准备好的纹理不再等待其他不可见区域的下载。

影像请求在离开下载队列后才开始计算 20 秒超时，并允许一次重试；失败瓦片每 20 秒重试，也可手动重试。地形目录 `layer.json` 在服务端单独缓存一小时并在启动时预热；缓存中不包含访问令牌，目录失败时允许浏览器直连原服务。凭据仍通过现有配置换取临时令牌，含令牌接口保持 `no-store`。地形和影像的首次下载速度仍受外部服务影响。

地形瓦片通过限定源的本地接口按需缓存，缓存命中不再访问远端。文件有效期一天，目录位于 `data/earth3d-cache/terrain-tiles/`，约 256 MiB 的容量阈值按分钟检查并清理较旧瓦片；浏览器可缓存成功响应一小时，错误响应不缓存。缓存键包含数据源、瓦片模板和扩展协议，文件中只保存地形数据，不保存令牌。缓存通道不可用时仍可直连原地形服务。

更新加载器版本时应重新验证：全球与区域图层混合、快速切换气压、云图刷新、地形开关、城市放大及外部地图服务中断。可用 `?view=city&debug=1` 和 `window.weatherEarth3D.captureMetrics()` 检查首块地形、影像级别、缓存估算、可见瓦片及待完成请求；普通页面不显示调试数据。

失败重试只处理已初始化的瓦片，避免 0.5.4 对外部索引中的原始子节点直接读取 `internal.loadingState` 而中断渲染。建筑更新异常会单独释放建筑层并安排重试，地形与风场渲染继续运行。

兜底球体的颜色先绘制，地形随后覆盖，最后单独补充遮挡深度；避免粗级别地形的平面三角形落入光滑球体内部时出现斑块，同时保留缺瓦片区域对背面风线的遮挡。
